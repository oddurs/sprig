The Sprig website

Ten seconds to get it. Thirty to try it.

On launch day the site has one job. A sceptical reader arriving from Hacker News understands Sprig from the first screen, and edits a real plan before deciding whether to scroll. Everything else, the docs included, is a structure built now and filled in as the roadmap ships.

revisedEvery part of this plan was argued both ways: seven calls changed, three things were added. The arguments.

Launch
Show HN on the first Tuesday after three gates pass: v0.1 with binaries, the WebAssembly playground, and a cleared name. Earliest 1 December 2026.
Domain
Decided by the name spike (cairn 0006). Until then, oddurs.github.io/sprig.
Stack
Astro and Starlight, static, with sprig-core compiled to WebAssembly, so the site and the CLI can't disagree.
Weight
No JavaScript until you type. Every page works with it turned off.
Tracking
None. No cookies, no analytics, no third-party requests.

The first minute

How a Hacker News reader tends to meet a new project, in order. This is a working assumption from watching launches, not measured data, and every section of the site answers one step of it.

  1. 0sReads the title

    Decides from about 80 characters whether to click.

    be described exactly by the title, with no surprises on arrival.

  2. 5sReads the first screen

    Looks for what it is, what it looks like and whether it's real.

    show the syntax and its computed result above the fold.

  3. 20sPokes at it

    Edits the example, ticks something, breaks it on purpose.

    respond instantly, with no signup and no server.

  4. 40sOpens GitHub

    Checks the README, licence, last commit, and whether the code exists.

    have a README that matches the site and a repo that's alive.

  5. 60s+Reads the comments

    The top comments often decide whether others click at all.

    answer the obvious questions before they're asked, and have the author in the thread.

The syntax is the pitch

          
The first screen is the format itself, editable, next to what it computes, with the nine marks as its legend. No illustration, no video, no waitlist. The computed side is rendered into the HTML at build time, so it reads correctly before any script loads.

          
On a phone the computed view comes first and tapping a mark is the interaction; the source opens behind a button. Narrow this window to see it.

          
For HNReaders judge a format by looking at it. A live example with no signup is the fastest way to prove the thing is real.

How it's built

      
The decisions that shape the build, each with the reason. Budgets follow, because HN readers do open the network tab.

    

    
    
      
  • Static and prerendered
    Every page is HTML at build time, including the hero's computed view. JavaScript only wakes the editor when you type. A static site can't fall over under a front-page spike.
    • 
      
  • Astro and Starlight, not the house Next.js setup
    Astro ships zero JavaScript by default and makes the playground its one island; Starlight brings the docs layout and Pagefind search. Even a static Next.js export ships the React runtime on every page, which breaks the budget below. This departs from the nextjs-site convention on purpose; overrule it if one toolchain across projects matters more.
    • 
      
  • The playground runs sprig-core as WebAssembly
    Never a JavaScript port. The one-implementation decision holds on the website too, and the same WebAssembly module renders the hero at build time in Node.
    • 
      
  • In the same repository, under site/
    A change to the format and the page describing it land in one pull request. A CI job builds the site and checks links when site/, spec/, docs/ or cairn/ change; the required job counts a skipped run as a pass, and the pre-push hook doesn't build it because it's slow.
    • 
      
  • Search is Pagefind, through Starlight
    A static index built at deploy time. No search service, no API key.
    • 
      
  • GitHub Pages, deployed from main
    Free, and one less account. The custom domain comes after the name spike.
    • 
      
  • No analytics
    GitHub traffic insights and the launch thread are enough feedback. Fonts are self-hosted and subset, so the page makes no third-party requests.
    • 
      
  • Sharing without a server
    A playground link carries the plan in the URL fragment, compressed with the browser's own CompressionStream, and browsers never send the fragment to a server. The FAQ says so.
    •

The launch

      
A Show HN on the first Tuesday, around 08:30 US Eastern, after three gates pass: v0.1 is out with binaries, the playground runs the WebAssembly core, and the name is cleared. The earliest is 1 December 2026, eleven days after v0.1 and clear of Thanksgiving week. A date that arrives before the gates moves.

    

    
The title

    
    

    
    
      
      
    
        
    A week before
    
        
      
          
    • A quiet preview for five to ten people who would put a real plan in it. They're asked for bugs, never for votes or comments on the day.
      • 
          
    • If the name stays Sprig, add one line to the comment saying Hack Club also has a project called Sprig, and why this one kept the name.
      • 
        
    
        
    On the day
    
        
      
          
    • Post the comment within a minute of the link, and stay for the first six hours.
      • 
          
    • Reply to every substantive comment in the first two hours, briefly and with thanks for criticism.
      • 
          
    • File real criticism as cairn items the same day, and link the item in the thread.
      • 
          
    • Check the site on a phone before posting: playground, spec anchors, install page.
      • 
        
    
        
    Never
    
        
      
          
    • Ask anyone to upvote or comment. It breaks the site's guidelines, and HN detects voting rings.
      • 
          
    • Argue with a dismissal. Answer the question inside it, or leave it.
      • 
          
    • Repost the same week if it sinks. Ship what the comments asked for; a later post with a real change is fair.
      • 
        
    
        
    It worked if
    
        
      
          
    • Every substantive criticism of the syntax is a cairn item within a day.
      • 
          
    • At least one decision is revisited or confirmed on the record because of the thread.
      • 
          
    • A week later, a handful of people are running a real plan in it. Stars measure the title, not the format.
      • 
        
    
        
    Afterwards
    
        
    r/rust for the parser and WebAssembly story, r/commandline for the CLI, This Week in Rust for the crate, and lobste.rs if a member offers an invite. One post each, spaced out, each saying what changed since the last.

    ~ changed
    Next.js, or something lighter?
    
        
    The house setup
    One toolchain across every project, following the nextjs-site conventions.
    Against
    Even a static Next.js export ships the React runtime on every page. That breaks this plan's own promise of no JavaScript before you type, on the homepage of a plain-text format, in front of the readers most likely to check.
    
        
    Ruling. Astro with Starlight: zero JavaScript by default, the playground as its one island, Pagefind search built in. It departs from the house setup on purpose; overrule it if consistency matters more than the budget.
    
      
    
      
    
        
    ~ changed
    A launch date, or a gate?
    
        
    A date
    Deadlines get things finished, and 1 December misses Thanksgiving week.
    Against
    The launch rests on three things that can slip: v0.1, the WebAssembly build and the name. A date that arrives first forces a launch without a playground or under a disputed name, and a first impression can't be redone.
    
        
    Ruling. Launch on the first Tuesday after all three gates pass. 1 December is the earliest, not the plan.
    
      
    
      
    
        
    ~ changed
    A comparison table on the landing page?
    
        
    For
    They'll ask about Org-mode and todo.txt within ten comments, so answer first.
    Against
    Every cell is a claim, and one wrong cell becomes the top comment. A table also frames Sprig as a feature checklist, the weakest way to see it.
    
        
    Ruling. The landing page answers in generous prose inside the questions. The verified table lives on /compare, where a correction is a small edit, not a headline.
    
      
    
      
    
        
    ~ changed

    Each section teaches exactly one concept.
    Against
