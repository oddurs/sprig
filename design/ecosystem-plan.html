How Sprig leaves the playground

A format is worth what reads it.

Markdown didn't win on syntax. It won when GitHub rendered it, every editor highlighted it, and a spec ended the dialects. Sprig needs the same three things, plus one reason nobody else has: a plan that people and software agents can both read, edit and check.

The language itself: Sprig, draft 0.2

Who it helps

Most of ordinary life runs on plans: care rotas, volunteer shifts, grant deliverables, school projects, public works. Today those plans live in apps that charge per seat, die without warning, and can't talk to each other. A plain file does none of that.

Families caring for someone

Siblings share one list that outlives any app, and everyone sees who's on what. It works on a cheap phone and reads cleanly with a screen reader, which a drag-and-drop board does not.

Volunteers

A line with no @name is an open shift. Claiming it means writing your name on it, and the list of open shifts is computed, so nobody keeps a spreadsheet in sync by hand.

Public projects

A council publishes its capital plans as files in a public repository. Progress and blockers come from the file, so a reporter can compare last month's version with this one instead of reading a press release.

Small charities

Grant deliverables in a text file cost nothing per seat, export to the funder's spreadsheet, and survive the person who set them up leaving.

Classrooms

Breaking a project into steps is a skill worth teaching. When the plan is the outline, the skill is visible, and a teacher reads every group's plan the same way.

People working with AI agents

The agent writes its plan where a person can read it, and stops at the question addressed to someone. Every change is a diff that can be reviewed or reverted. This is the group Sprig has to win first.

What made other formats fly

Plain-text formats have a long record of succeeding and failing for reasons that have little to do with how good the syntax was. In order of arrival:

  1. 1998

    iCalendar

    A dull standard that every calendar learned to speak.

    LessonInterop beats features. Any tool that emits it is useful on day one.

  2. 1999

    RSS

    Open and loved, then sidelined when the big platforms stopped offering feeds.

    LessonBe useful even when the largest player ignores you.

  3. 2003

    Org-mode

    The most capable plain-text planner ever made, and still mostly an Emacs thing.

    LessonA format is only as portable as its best implementation.

  4. 2004

    Markdown

    Became universal once GitHub, Reddit and Stack Overflow rendered it.

    LessonDistribution, not syntax. Be rendered where people already look.

  5. 2006

    todo.txt

    One file, no server, and dozens of apps, because the format fits on a page.

    LessonSmall enough to implement in a weekend means many implementations.

  6. 2014

    CommonMark

    A decade of Markdown dialects, finally pinned down by a spec made of examples.

    LessonWrite the test suite before the second parser exists.

  7. 2014

    Mermaid

    Diagrams as text. It existed for years before anyone much noticed.

    LessonOne host rendering it natively (GitHub, 2022) changed everything.

  8. 2026

    Sprig

    Plans as text, shared by people and agents.

    LessonStill to be learned. The rest of this page is the attempt.

Start narrow

A format can't win everyone at once. It wins one group so thoroughly that the others notice.

First: developers working with AI agents

  • They already live in plain text and git. A new file type costs them nothing to try.
  • Agents need a plan format now. Today's agent plans are ad-hoc Markdown checklists that nothing can compute over.
  • It's the strongest case for legibility. A person can see what an agent intends before it acts, and change it by editing a line.
  • It's where Markdown started. Developers first, then everyone who read what developers published.

Not first

  • A consumer grocery app. Consumer distribution is a war, and formats don't win wars. The app comes once the format is everywhere.
  • A hosted service. It would turn an open format into a product people eventually have to leave.
  • A Jira replacement. Bridges first. Whether to replace anything is the users' call.

Where this is weak

The plan fails if any of these is waved away. Each has an answer, and some of the answers are partial.

Teams won't leave their tracker

They shouldn't have to. Two-way sync and the calendar feed make Sprig useful next to Jira before it replaces anything.

Dialects

Markdown's decade of disagreement came from a thin spec and many parsers. Sprig ships the conformance suite before 1.0 and one core that every official tool shares.

Two people, one file

One item per line merges well in git. Two people ticking the same list in a shop does not, and the phone app needs a real answer: a CRDT or line-level merge. This is the hardest engineering problem on the page, and it's still open.

"File" means nothing to most phone users

So the phone app never says it. Folders sync underneath, and the family sees a shared list.

Permissions are all-or-nothing per file

That's also the answer. Split a plan by audience into files, set access per file, and graft them together for the people allowed to see the whole thing.

The name may be taken

Hack Club already has a project called Sprig, and there's a well-known Go template library by that name. The roadmap treats this as a blocking question before anything is published.

Agents could flood plans with noise

sprig check can cap how many items an agent may add per change, and every agent edit arrives as a reviewable diff. Legibility is the point, so it has to be defended.

Plain text can't do everything

Attachments, images and time tracking stay out of the format. Links point to them. A format that tries to hold everything ends up as a database nobody can read.

Who pays, and how we'd know it worked

Open formats die when nobody is paid to maintain them. They also die when the people paying start to own them.

Grants for the foundation

Funders of open infrastructure, such as NLnet and the Sovereign Tech Agency, pay for exactly this kind of spec, test-suite and parser work.

Paid sync, free format

The phone app is free. Hosted sync and sharing is a subscription, the way Obsidian Sync pays for Obsidian. Syncing through git or Syncthing stays free forever.

Never

Selling plan data, or any feature that only the paid app can read. If a file can't be opened without paying, the format has failed.

It worked when

  • A thousand public repositories carry a PLAN.sprig.
  • A parser written by strangers passes the whole conformance suite.
  • A family has used the phone app for a shared list for three months without learning what Sprig is.
  • One public body publishes a real plan as Sprig, and someone outside it reads the diff.
  • There's a Sprig tool nobody on the core team has heard of.
