A plain-text format for plans

Sprig.

A shopping list and an eighteen-month build use the same handful of marks, nest as deep as you like, and link across files so small plans add up to a big one.

.sprig  ·  UTF-8  ·  indentation is structure  ·  no depth limit

0.2Answer lines, branch grafts, dates stored as dates, and no header block. The arguments behind each change.

One construct, all the way down

Sprig takes the indentation of an outline, the one-character status of todo.txt, the tags of TaskPaper and the links of a wiki, and drops everything else.

Everything is an item

A carton of eggs and a quarter-long milestone are the same thing: a line that starts with a mark. Even the title is an item, so its @owner and dates flow down to everything under it.

The file is the truth

The first character is the status and dates are real dates. A plan reads the same in cat, in a diff, or a year from now, and the view never says something the text doesn't.

Context sits with the work

Unmarked lines under an item are its notes. Decisions get their own line, starting with =, so the reason stays next to the work it changed.

Files graft together

+ [[kitchen]] mounts a file as a branch and + [[kitchen^oven]] mounts one part of it. Progress, estimates and blockers roll up across files.

Playground

Six linked files for opening a bakery. The view re-reads the source as you type; tick a mark and the source changes too. dana.sprig is one person's week, grafted from branches of the others. Answer the naming question in bakery.sprig and the window lettering in launch.sprig unblocks.

Same syntax at every size

      
Nothing changes as a plan grows. You add an owner when there's more than one person, anchors when something waits on something else, and a second file when one gets long.

    

    

      
A listA title and some marks. That's a valid file.

      
A weekendDates, two people, one thing waiting on another.

      
A projectPriorities, a settled question, one graft.

      
A companyNothing but grafts. Each team owns a file.

    

  


  

    

      
The whole language

      
Line starts say what a line is. Tokens inside a line add facts about it. Everything else is plain text, and stays readable as plain text.

    

    

      

        
Line starts

        

          
- ~ x / >
To do, doing, done, dropped, later

          
? 
Question. Open until it has an answer.

          
= 
Answer or decision, attached to the item above

          
# 
Group. No status of its own; it shows what its children add up to.

          
+ [[file]]
Graft that whole file here

          
+ [[file^id]]
Graft one branch of it

          
plain text
A note on the item above

          
// 
Comment. Never rendered.

          
\- 
Escape: a note that happens to start with a mark

        

      

      

        
Inside a line

        

          
@dana
Who. Flows down until a child names someone else.

          
#finance
Tag. No space after the #, which is how it differs from a group.

          
! !! !!!
Priority

          
^signed
Anchor: a name other lines can point at

          
after:^signed
Waits on that item. Blocked until it's done.

          
[[lease^signed]]
Link to a file, or to an item in one

          
due:2026-10-03
Stored as ISO. Type fri, +2w, oct3 or tomorrow and the editor converts it.

          
est:4h
Hours, days (8h) or weeks (5d). Sums up the tree.

          
every:fri
Recurring. Ticking it moves due: to the next one.

          
key:"two words"
Any other field. Quote values that have spaces.

        

      

      

        
The file

        

          
line 1
The title. It's the root item, so its tokens apply to the whole file.

          
indentation
Relative. Deeper than the line above makes a child. Formatters write two spaces.

          
.sprig
Extension. UTF-8, LF line endings.

          
one file
Can be a whole grocery list. Grafts join many files into one plan.

        

      

    

  


  

    

      
How a file is read

      
The parser on this page follows these steps in order. They are the spec.

    

    

      
    
        
  1. Title. The first non-blank line is the title, unless it starts with a mark. It is the root item and takes tokens like any other item.
    2. 
        
  2. Classify each line by its first characters. A mark and a space (- ~ x / > ? # +) start an item. =  is an answer. // is a comment. \ escapes. Anything else is a note.
    3. 
        
  3. Indentation picks the parent. A line belongs to the nearest line above it with less indentation. Blank lines only separate note paragraphs.
    4. 
        
  4. Lift the tokens. Split on whitespace, keeping quoted values whole. @ # ^ ! and key:value become metadata. What's left is the text.
    5. 
        
  5. Status flows down, progress flows up. x, / or > settles a whole branch. A ? with an answer is done. Groups and grafts show what their leaves add up to. Recurring items are upkeep and don't count toward progress.
    6. 
        
  6. Who flows down from the title and from any @name, until a child names someone else.
    7. 
        
  7. Blocked is computed, never written. An open item is blocked while anything in its own after: list, or an ancestor's, is unfinished.
    8. 
        
  8. Grafts resolve by file name next to the current file; ^id narrows to one branch. A graft that loops back to a file above it is an error on that line.
    9. 
        
  9. Dates don't need a clock. ISO dates mean the same thing forever. Relative words are read against today as a courtesy, and editors should expand them before saving.
    10. 
      

      
    

  


  

    

      
Arguments, settled

      

        
Sprig is opinionated on purpose. Every rule here was argued both ways before it went in, and the ones that lost are written down so nobody has to argue them again.

        
~ 5 changed+ 2 addedx 3 kept/ 2 rejected

      

    

    

      

        
~ changed
Groups: a trailing colon, or a mark?

        

          
For the colon
TaskPaper does it, and Flour: looks like a heading in any text editor.

          
Against
Every note that ended in a colon, like "Two options:", quietly became a heading and took the lines below it. A rule that fires by accident is a bad rule.

        

        
Ruling. Groups start with # , the same way every other line starts: one character, then a space. Markdown viewers show it as a heading too.

      

      

        
~ changed
Should a file have a header block?

        

          
For
owner: @dana on its own line is easy to scan, and front matter is familiar.

          
Against
It was a second syntax for fields: key: value up top, key:value everywhere else, with different rules about spaces.

        

        
Ruling. The title line is the root item and takes the same tokens as any item: Open the bakery @dana target:2026-12-05. A value with spaces goes in quotes.

      

      

        
~ changed
Can a date be relative?

        

          
For
due:fri is the fastest thing to type and it's how people talk.

          
Against
A week later the same file means something else. A plan whose meaning depends on the day you open it can't be diffed, shared or trusted.

        

        
Ruling. Dates are stored as ISO. fri, +2w and oct3 still work while typing, and the editor converts them when you leave the line. The 0.1 exception that let due:oct 3 swallow the next word is gone.

      

      

        
+ added
How does a question end?

        

          
Just tick it
x works for everything else, so there's nothing new to learn.

          
Against
Ticking a question throws away the answer, which is often the most valuable line in the plan.

        

        
Ruling. An answer line starts with = . A ? with an answer under it is done, and anything waiting on it unblocks. grep '^ *= ' over a folder is the decision log.

      

      

        
x kept
Should a parent's status be computed?

        

          
For
No more going back to tick a parent after ticking its last child.

          
Against
The file would say - while the view says done. Once the view contradicts the text, the text stops being the plan.

        

        
Ruling. The file stays the truth. The view flags a parent whose children are all done with "all done · tick it". Want a computed status? Use a # group. That's what groups are for.

      

      

        
+ added
Graft a branch, or only whole files?

        

          
Files only
One file, one owner. Easy to reason about.

          
Against
A person's week, or a release, is naturally built from parts of several plans.

        

        
Ruling. + [[lease^terms]] mounts one branch, and ticking it there edits the original line. A branch grafted twice into one tree counts twice, so don't.

      

      

        
~ changed
What does ticking a recurring item do?

        

          
Keep a history
Append a line per completion, so the file shows every week it happened.

          
Against
A plan that grows a line every week turns into a diary. Version control already keeps history.

        

        
Ruling. Ticking an item with every: moves its due: to the next occurrence and leaves it open. Recurring items are upkeep, so they don't count toward progress.

      

      

        
~ changed
Exactly two spaces per level?

        

          
For
One way to indent, so files look the same everywhere.

          
Against
Rejecting a file over a stray third space is hostile, and pasted text arrives indented every way there is.

        

        
Ruling. Indentation is relative: deeper than the line above makes a child. Formatters write two spaces. Parsers accept whatever they're given.

      

      

        
x kept
Generate ids from the item's text?

        

          
For
No ^anchors to write by hand.

          
Against
Rewording an item would silently break every link that points at it.

        

        
Ruling. Anchors stay explicit. Only items that something points at need one.

      

      

        
x kept
A letter for done?

        

          
Use a symbol
Every other mark is punctuation, and a note that starts with "x " turns into an item.

          
Keep x
It's how people tick paper forms, and todo.txt proved it works in plain text. Nobody has to learn it.

        

        
Ruling. x stays. A note that really starts with "x " takes a backslash.

      

      

        
/ rejected
Numbered steps for sequences?

        

          
For
1. 2. 3. is familiar and would chain dependencies for free.

          
Against
A step still needs a status, so the number fights the mark for the start of the line. Real work is rarely strictly serial either: plumbing and electrics run side by side.

        

        
Ruling. No. Write after: where the order is real.

      

      

        
/ rejected
Accept Markdown checkboxes?

        

          
For
Millions of - [ ] lists already exist.

          
Against
Two spellings for every status, forever, in every tool that reads Sprig.

        

        
Ruling. No. Converting old lists is a one-time script's job, not the parser's.
