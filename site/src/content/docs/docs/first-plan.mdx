This takes about five minutes and needs nothing installed. Each step is a
complete Chea file; open it in the playground to see what Chea computes from
it, then change it and watch the result move.

The last step takes the same plan to the terminal with the `chea` command.

## 1. A list

Every item is a line that starts with a mark and a space. `-` is something to do
and `x` is done. The first line is the title.

```chea
Move flats

- Pack
- Book a van
x Tell the landlord
```

<PlayLink files={{ 'move.chea': `Move flats

- Pack
- Book a van
x Tell the landlord` }} />

The view shows one of three done. Tick *Pack* in the view and the source changes
too: the file is always the truth.

## 2. Break it down

Indent to put items inside another. There's no limit to how deep, and each
parent adds up what's beneath it.

```chea
Move flats

- Pack
  x Books
  - Kitchen
  - Bathroom
- Book a van
x Tell the landlord
```

<PlayLink files={{ 'move.chea': `Move flats

- Pack
  x Books
  - Kitchen
  - Bathroom
- Book a van
x Tell the landlord` }} />

*Pack* now shows 1 of 3. A parent keeps the mark you give it: when all its
children are done, the view suggests ticking it rather than doing it for you.

## 3. Say what waits

Give an item an anchor with `^name`, and make another wait on it with
`after:^name`. Anything waiting is blocked until what it waits on is done.

```chea
Move flats

- Pack  ^pack
  x Books
  - Kitchen
- Book a van  ^van
- Move everything  after:^van  after:^pack
```

<PlayLink files={{ 'move.chea': `Move flats

- Pack  ^pack
  x Books
  - Kitchen
- Book a van  ^van
- Move everything  after:^van  after:^pack` }} />

Switch the view to **Next up**: *Kitchen* and *Book a van* are ready, and *Move
everything* is waiting on two things. Tick *Pack* and *Book a van* and it moves to ready.

## 4. Ask, then answer

A line starting with `?` is a question. Write the answer underneath with `=`, and
the question counts as done. The decision stays in the file, next to what it
decided.

```chea
Move flats

? Keep the old sofa?
  = No. It won't fit in the lift.
- Sell the sofa
```

## 5. People and dates

`@name` says who. It flows down, so a name on the title owns the whole file until
an item names someone else. Dates are written `due:2026-10-17`; in the
playground you can type `due:fri` and it becomes a real date when you press
Enter.

```chea
Move flats  @me

- Book a van  due:2026-10-16
- Carry the heavy boxes  @jo
```

## 6. Split it into files

When a plan grows, move a branch into its own file and graft it back with
`+ [[name]]`. Progress and blockers carry across.

{/* file: move.chea */}
```chea
Move flats

+ [[packing]]
- Book a van
```

{/* file: packing.chea */}
```chea
Packing

x Books
- Kitchen
- Bathroom
```

## 7. In the terminal

Install the `chea` command, with Rust installed ([rustup.rs](https://rustup.rs)):

```sh
cargo install --locked --git https://github.com/oddurs/chea chea-cli
```

Save the two files from step 6 as `move.chea` and `packing.chea` in one
folder, and ask what can be done now. Grafted items come with their file:

```console
$ chea next move.chea
- Kitchen     Packing
- Bathroom    Packing
- Book a van  Move flats

3 ready
```

`chea check` reads the same files and prints nothing when the plan holds
together. Misspell the graft and it says where:

```console
$ chea check move.chea
```

{/* edit: move.chea: [[packing]] => [[pakcing]] */}
```console
$ chea check move.chea
move.chea:3:3: error[C0101]: no file named pakcing.chea
```

It exits 1 on an error, so it can guard a repository. In GitHub Actions, the
[Chea action](https://github.com/oddurs/chea/tree/main/action) checks every
plan and summarises what each pull request did to them:

```yaml
- uses: oddurs/chea/action@main
```

## 8. Work it from your editor, and hand it to an agent

Fix the graft again, and tick the van as booked:

{/* edit: move.chea: [[pakcing]] => [[packing]] */}
```console
$ chea tick van
move.chea:4  x Book a van
```

A ref is any words that match one item, an `^anchor`, or `file:line`. In VS Code,
Neovim or any editor with a language server, the same tick is one action on the
line, and problems show as you type: [set up your editor](/docs/editors/).

For a project, the plan lives at the root as `PLAN.chea`. To have a coding
agent read it before it starts and keep it up to date as it works, add the
instructions to the file the agent reads:

```console
$ chea mcp --instructions --write AGENTS.md
```

Then register the MCP server with the agent. `chea mcp --config` prints the
snippet for `.mcp.json`. The agent can then ask what is next, tick what it
finishes and add the steps it plans, and every change it makes shows up as a
diff: [plans for coding agents](/docs/agents/).

- The [settled arguments](/decisions/) say why each rule is the way it is.
